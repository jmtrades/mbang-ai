# Operator AI — Enterprise Engineering Standard

Status: binding. Every module in `operator_ai/` and `web/src/` must meet every requirement below. Each requirement
has an id (`ARCH-3`, `SEC-7` ...) so a test, a CI gate, a code review or a PR description can cite it. A requirement
without a stated measure is not a requirement; every line here names the command, test or artefact that proves it.

This standard was written from nine challenged audits (backend architecture, API contracts, frontend architecture,
security, reliability/ops, quality engineering, AI runtime, data/compliance, product parity) against commit `d6c998b`.
Where the audits disagreed, the decision and the reason are recorded in `docs/REBUILD_PLAN.md` § "Decisions".

Conventions: "MUST" is pass/fail. `grep`/`wc` measures run from the repo root. "the suite" is `pytest -n auto` on
Linux with the pinned interpreter. A requirement marked **[gate]** fails CI; one marked **[review]** is checked in
code review with a citation in the PR.

## 0. Product invariants (INV) — never weakened, never configurable off

These are the product. They override any other requirement, any performance target, any parity feature. A change
that weakens one of them is rejected regardless of who asks.

| id | invariant | measure |
|---|---|---|
| INV-1 | **Approval before send.** No message, invite, ad change, CRM move, post or payment-affecting action reaches a real person or a real external system unless a human with the right to decide that kind approved exactly that content (body hash + version) in this tenant. Scheduled, cadence and mission-generated items are no exception. Mock transports run only in demo workspaces. | **[gate]** `tests/contract/test_invariants.py::test_no_path_to_sent_without_approval` (hypothesis stateful machine over the queue FSM); `tests/test_arch.py::test_only_queue_dispatcher_calls_senders` asserts `live.senders.send` is imported by exactly one module (`delivery/dispatcher.py`); every `live/*` adapter requires an `Approval` token object that only `queue.transition(to="approved")` can mint. |
| INV-2 | **No impersonation.** The product never speaks *as* a real person: persona rules (`impersonation`, `persona_in_outreach`, `persona_autobio`, `speculative_attribution`) stay block-severity in every mode; AI answers are labelled as AI; no outbound item carries a real person's name as sender unless that person is the signed-in actor. | **[gate]** `tests/test_persona.py` block matrix must stay green and may only grow; `guardrails.RULE_PLUGINS` registration is validated at boot (ARCH-9). |
| INV-3 | **No voice cloning.** No code path synthesises speech in a real person's voice; TTS uses a neutral voice; no model, sample or embedding of a real person's voice is stored. | **[gate]** `tests/test_arch.py::test_no_voice_clone_dependencies` (deny-list of packages/APIs: elevenlabs voice-add, resemble, coqui XTTS speaker-wav, openai voice-create, any `speaker_wav`/`voice_sample` parameter); `grep -rniE "clone(d)? voice|voice.?clon" operator_ai web/src` returns only denial text. |
| INV-4 | **No income claims, no guarantees, no fake proof.** `income_claim`, `guarantee`, `fake_testimonial`, `unverified_result`, `fake_shoutout`, `planted_question` stay block-severity in every mode, including the owner's own drafts, Academy material and AI answers; proof records (`claims.py`) are the only exemption path and require on-disk evidence. | **[gate]** `tests/test_guardrails.py` (146+ cases, bypass matrix) plus the hypothesis metamorphic suite (QE-11) must stay green; the rule table in `docs/GUARDRAILS.md` is generated from code (`scripts/gen_guardrails_doc.py`, CI diff). |
| INV-5 | **Honesty about mode.** Every AI-produced artefact carries its mode (live AI / replay / rules) in data and, for owner and staff roles, in the UI; fixture-corpus output is labelled "Demo material"; no marketing claim in `docs/` exceeds what a named test proves. | **[gate]** `tests/test_phase10_ops.py::test_scorecard_evidence_exists`; `docs/audits/*/claims_to_avoid` lint. |

## 1. Architecture (ARCH)

| id | requirement | measure |
|---|---|---|
| ARCH-1 | **Layered monolith, enforced.** `operator_ai/kernel/` (config, logging, clock, text, db/{engine,migrations,uow,dialect}, tenancy, auth, audit, events/outbox, jobs, fsm, guardrails, runtime, ratelimit, errors, redact) imports nothing from `operator_ai/domain/` or `operator_ai/api/`; `domain/` imports kernel only; `api/` imports both; `features.py` is the only module that imports every feature. | **[gate]** import-linter contracts in `pyproject.toml` (`layers` + `independence`), run by `tests/test_arch.py::test_import_layers`; function-level imports counted (AST walk), not just module-level. |
| ARCH-2 | **Acyclic import graph** counting function-level imports; the only permitted lazy import is inside `features.load()`. | **[gate]** `tests/test_arch.py::test_no_import_cycles` (grimp/AST). |
| ARCH-3 | **Module size cap.** No Python module > 800 lines, no function > 80 lines, no function with cyclomatic complexity > 15; no TSX file > 600 lines. | **[gate]** `tests/test_arch.py::test_module_sizes`; `radon cc -n C` = 0 hits (CI); ESLint `max-lines: 600`. |
| ARCH-4 | **One state machine per stateful entity**, declared as data (`TRANSITIONS: dict[tuple[str,str], Guard]`) and driven by one `transition()` on `kernel.fsm` that claims (`UPDATE ... WHERE id=? AND status IN expect RETURNING *`), validates the edge, writes the row, the audit row and the outbox event in one unit of work. Entities: queue item, job, mission step, cadence, action, party pipeline stage, webinar send, run, operation, escalation. | **[gate]** `tests/test_arch.py::test_no_raw_status_writes` asserts `grep -rnE "(UPDATE|DELETE FROM|INSERT INTO) (queue|jobs|cadences|actions|mission_steps|pipeline_stages)\b" operator_ai \| grep -v "<owning repo file>"` = 0; exhaustive transition-table tests per entity (every (from,to) pair allowed-with-guard or rejected). |
| ARCH-5 | **Unit of work.** Any operation touching more than one row runs inside `with uow(tenant) as u:` (one connection, `BEGIN IMMEDIATE`); repositories take `u`; `Tenant.db()` outside kernel is gone. | **[gate]** `grep -rn "tenant.db()" operator_ai/domain operator_ai/api` = 0; crash-injection tests (REL-9) prove atomicity. |
| ARCH-6 | **Transactional outbox.** Hooks, domain events, job enqueues and audit rows written by a state change are rows in `outbox`/`audit` inside the same transaction; a relay delivers outbox rows in id order with `handled_events(subscriber, event_id)` idempotency, backoff and dead-letter. No in-process synchronous subscriber side effects. | **[gate]** `tests/kernel/test_outbox.py` (rolled-back emit delivers nothing; crash after status write still delivers exactly once; failing subscriber retried without blocking others). |
| ARCH-7 | **Three process roles** (`operator_ai api`, `operator_ai worker`, `operator_ai scheduler`) sharing the database; no correctness-bearing state in process memory (rate limits, budgets, locks, claims, registry cache without version check). Until the split ships, startup refuses `--workers > 1` and a second instance on the same data dir. | **[gate]** `tests/test_arch.py::test_no_module_level_mutable_state_outside_allowlist` (AST scan; allowlist entries carry a TTL/version justification); `tests/integration/test_process_model.py` boots the three roles as subprocesses. |
| ARCH-8 | **Jobs are durable and leased**: `jobs(id, kind, key UNIQUE, scope, payload, status IN (queued,running,done,failed,dead), priority, attempts, max_attempts, next_at, lease_until, heartbeat_at, worker_id, generation, last_error, dead_at)`; per-kind `POLICY` (max_attempts ≥ 5, backoff 2 s → ≥ 1 h cap with full jitter, concurrency cap, timeout, lease, key_ttl); handlers declare `idempotent=True` and are proved so; `enqueue` returns the existing id on key collision via `INSERT ... ON CONFLICT(key) DO UPDATE ... RETURNING id`. | **[gate]** `tests/kernel/test_jobs.py` (lease reclaim by second worker, heartbeat keeps a long job alive, backoff schedule, dead-letter, concurrent enqueue same id, every registered handler run twice = identical DB state). |
| ARCH-9 | **Feature registration validated at boot.** `features.py` lists `FEATURES: list[Feature]` (hooks, subscribers, job handlers, ticks, seeders, schema files, guardrail plugins); a decorator-registered hook/handler/subscriber/plugin in a module not in `FEATURES` fails startup with a named error; registration is eager in lifespan, never lazy from a hot path. | **[gate]** `tests/test_integration_wiring.py::test_every_registered_hook_is_declared`; `tests/test_arch.py::test_no_lazy_handler_load` (`grep -rn "handlers.load()" operator_ai` only in lifespan). |
| ARCH-10 | **Scheduler is leased and fair.** `tick_leases(tenant, name, due_at, every_s, lease_until, last_ok_at, last_ms, lag_ms, last_error, generation)`; the scheduler only leases due rows and enqueues `(tenant, tick)` jobs with per-kind deadlines; a slow tenant cannot delay another tenant's `dispatch_due` by more than one worker slot; ticks never write user-facing `runs` rows. | **[gate]** `tests/kernel/test_scheduler.py` (two schedulers over one DB run each tick once; slow tick in A does not delay B; lag metric recorded). |
| ARCH-11 | **Every intermediate state** (`sending`, `drafting`, `executing`, `running`, `ready`, `claimed`) carries `claimed_at`/`lease_until` and a `generation`; `recover_all(tenant)` runs every minute and at boot (previous-generation rows recovered within one tick); each has a crash-injection test asserting exactly-once effects. | **[gate]** `tests/recovery/test_*` one per state; `OPERATOR_CRASH_AT=<marker>` helper. |
| ARCH-12 | **Domain model: one party aggregate.** `parties`, `contact_points`, `consents`, `suppressions`, `pipeline_stages`; `PIPELINES = {name: {stages, transitions, terminal}}`; `stages.move()` the only stage writer; `dnc(party)` suppresses every contact point; `is_contactable(party, channel)` the single check the dispatcher uses. | **[gate]** `tests/domain/test_parties.py` (STOP on any channel blocks every channel; won→new rejected; CSV + Meta lead same email = one party). |
| ARCH-13 | **No duplicated kernel helpers** (`_int`, `local_day_start`, `next_morning`, `e164`, `canonical_email`, `_party_row`, `_user`, email regex): one definition in `kernel/text.py` / `kernel/clock.py` / `domain/parties`. | **[gate]** `tests/test_arch.py::test_no_duplicate_helpers`. |
| ARCH-14 | **Tenant time zone.** `tenant_timezone` (IANA) drives every day boundary, cap window and "next morning". | **[gate]** `tests/kernel/test_clock.py` (Australia/Sydney and America/Los_Angeles on a UTC server). |
| ARCH-15 | **Application factory.** `create_app()` builds the app; nothing is created at import time; `uvicorn operator_ai.app:create_app --factory`; `STARTED`/generation live in `kernel/process.py`. | **[gate]** `python -c "import operator_ai.app"` opens no DB, starts no thread (test with patched `sqlite3.connect` and `threading.Thread`). |
| ARCH-16 | **Repository layer and dialect seam.** SQL for an aggregate lives in exactly one `*_repo.py`; SQLite-only syntax (`INSERT OR IGNORE`, `json_set`, `PRAGMA table_info`) is confined to `kernel/db/dialect.py`; the kernel suite runs against SQLite and Postgres. | **[gate]** `grep -rlE "INSERT OR IGNORE|json_set\(|json_extract\(|PRAGMA table_info" operator_ai \| grep -v kernel/db` = 0; CI matrix `DB=sqlite,postgres` for `tests/kernel`. |

## 2. Data, schema and compliance (DATA)

| id | requirement | measure |
|---|---|---|
| DATA-1 | **Versioned migrations.** Ordered files `operator_ai/schema/NNNN_name.sql\|py` (per package allowed, collected and sorted), `schema_migrations(version INTEGER PRIMARY KEY, name, checksum, applied_at)`, applied inside `BEGIN IMMEDIATE` under an fcntl lock after re-reading the version inside the transaction; `python -m operator_ai migrate --check\|--plan\|--apply [--tenant]`; the app refuses to serve a DB whose version is ahead of the code and refuses to serve one behind it unless `OPERATOR_AUTO_MIGRATE=1`; `COLUMN_MIGRATIONS` deleted. | **[gate]** `tests/kernel/test_migrations.py` (fixture DB per released tag → head equals fresh create; two subprocesses migrate concurrently, exactly one applies, both exit 0; downgrade refused). |
| DATA-2 | **Constraints.** Every status column has `CHECK(status IN (...))` generated from the Python enum; `NOT NULL` on status/created/kind; real FK columns with `ON DELETE` rules; `UNIQUE(channel, ext_id, COALESCE(provider_id,''))` on `inbound_messages`; `UNIQUE(webinar_id, registrant_id, template_key)` kept. | **[gate]** `tests/kernel/test_schema.py` (every enum matches its CHECK; `PRAGMA foreign_key_check` empty on the seeded demo; every `party_id` referenced by queue meta/cadences/conversations resolves). |
| DATA-3 | **Hot paths use indexes, never `json_extract` in WHERE.** Generated columns `owner_user_id, prospect_id, conversation_id, tag, build_id, chain_id` on `queue` with indexes `(status, owner_user_id, id)`, `(conversation_id, status)`, `(tag, status)`; `audit(kind,id)`, `audit(at)`, `login_fails(key,at)`, `sessions(expires)`, `runs(agent,id)`, `app_events(created)`. | **[gate]** `tests/kernel/test_query_plans.py`: `EXPLAIN QUERY PLAN` shows `USING INDEX` for the ten hottest queries; `grep -rn "json_extract" operator_ai \| grep -v kernel/db` = 0. |
| DATA-4 | **Durability.** Tenant DBs `PRAGMA synchronous=FULL`, WAL, `busy_timeout=3000` on request paths (30 s only in maintenance), `wal_autocheckpoint=1000`; SQLITE_BUSY handled by a bounded retry (3 attempts, jitter) at the unit-of-work boundary and mapped to `503 + Retry-After`, never a 30 s stall into a 500. | **[gate]** `tests/kernel/test_busy.py` (contended write → 503 in < 5 s); crash-consistency test for `sent_at` (subprocess killed mid-write). |
| DATA-5 | **Retention.** `RETENTION = {login_fails: 1 d, expired sessions: 0 d, jobs done/dead: 30 d, runs: 180 d, app_events: 90 d, webhook_events: 30 d, outbox delivered: 7 d, ai_replays: LRU by size, audit: 2 y unless legal_hold}` applied by a nightly maintenance tick in 1,000-row batches, followed by `PRAGMA optimize` and `wal_checkpoint(TRUNCATE)`; table sizes on the owner ops page. | **[gate]** `tests/kernel/test_retention.py` (prunes only outside window, respects legal hold; login latency flat after 100k `login_fails` rows). |
| DATA-6 | **Audit is transactional and tamper-evident.** `audit.log(u, actor, kind, detail)` writes inside the caller's unit of work; `kind` validated against `KINDS`; `prev_hash`/`hash` SHA-256 chain plus HMAC with `OPERATOR_AUDIT_KEY`; `BEFORE UPDATE/DELETE` triggers raise ABORT; daily anchor rows; weekly verification raises an escalation and an ops alert on a break; unauthenticated failures aggregated one row per (kind,key) per minute; detail capped at 4 KB; every row carries `request_id`, `version` and `body_sha256` where applicable. | **[gate]** `tests/kernel/test_audit.py` (edited row breaks verify at that id; 10k bad logins ≤ 15 rows; unknown kind raises in tests). |
| DATA-7 | **Encryption at rest.** Vault blob `OPV2` with per-tenant DEK wrapped by a KEK outside the data dir (`OPERATOR_KEK_FILE` or KMS adapter), key version in header, `vault rotate` command, `OPV1` migrated on first read; backup archives encrypted with `age` before leaving the box; owner password never written to disk (one-time setup link). | **[gate]** `tests/kernel/test_vault.py` (undecryptable with the data dir alone; rotation keeps fields readable; archive magic is `age-encryption`; `owner_password.txt` never created). |
| DATA-8 | **Public tokens hashed and time-boxed.** Every bearer-link column stores SHA-256 only; `expires_at` per kind (proposal 30 d, intake 14 d, mini session 24 h, webinar unsubscribe event+90 d, invite 7 d, reset 30 min); single-use where the action is single-use; revocable from the UI; never in access logs. | **[gate]** `tests/test_token_columns.py` schema scan; expired/revoked → 404; second accept → 410. |
| DATA-9 | **Consent and suppression are first-class.** `consents(party_id, scope, state, evidence, at)`, `suppressions(address_key UNIQUE, channel, reason, source_party)`; `lawful_basis` required on every imported prospect row; STOP/unsubscribe on any channel suppresses every contact point of the party; CAN-SPAM footer/postal and RFC 8058 one-click kept. | **[gate]** `tests/domain/test_consent.py`; `tests/test_delivery.py` footer/unsubscribe tests kept. |
| DATA-10 | **Subject export and erasure.** `POST /t/{tid}/api/v1/parties/{id}/export` (JSONL of every row referencing the party) and `/erase` (anonymise with an audit row and a merge log); per-tenant export/delete scripts; documented in `docs/SECURITY.md`. | **[gate]** `tests/domain/test_dsar.py` (export contains every referencing table; erase leaves no PII, keeps audit chain valid). |
| DATA-11 | **Backups: RPO ≤ 1 min (continuous WAL replication), RTO ≤ 30 min**; snapshots cover the whole tenant directory with a deny list and a `manifest.json` (sha256, size, `schema_migrations` version per DB); per-tenant backup/restore; restore refuses while the app is alive, swaps per entry (mount-point safe), verifies every DB-referenced file, and quarantines `scheduled/approved/sending` items to `needs_attention` with reason `restored from backup <stamp>`. | **[gate]** `tests/ops/test_backup_restore.py` (roundtrip incl. claims evidence and drive_inbox; refuse on live /health; EBUSY rename; manifest tamper; restore-then-tick dispatches nothing pre-restore); nightly CI restore drill. |
| DATA-12 | **Proof-record integrity.** `claims.current()` returns `needs_evidence` when any referenced evidence file is missing; evidence files are in the backup manifest. | **[gate]** `tests/test_claims.py::test_missing_evidence_demotes_record`. |
| DATA-13 | **Postgres parity for the kernel.** The repository layer and dialect seam let `tests/kernel` pass against Postgres (schema-per-tenant); hosted deployments use it; self-hosted keep SQLite-per-tenant. | **[gate]** CI job `kernel-postgres`. |
| DATA-14 | **Per-box capacity documented and proved**: ≤ 200 tenants, ≤ 2 GB per tenant DB, index budget 512 MB, numbers from `scripts/load_test.py` at N tenants. | **[gate]** `docs/CAPACITY.md` generated by the nightly load job. |

## 3. API contract (API)

| id | requirement | measure |
|---|---|---|
| API-1 | **Contract-first.** Every operation declares `response_model` from `operator_ai/schemas/`; a tag per module; `operation_id = <module>.<function>`; `info.version` from `importlib.metadata`; `securitySchemes {cookieAuth, mcpBearer}` and `security` on every non-public operation; `x-required-role` emitted from the dependency tree; shared `responses` for 401/403/404/409/412/413/415/422/428/429 referencing one `Problem` schema. | **[gate]** `tests/contract/test_openapi.py` (100 % of ops have a `$ref` 2xx schema, tag, security-or-public); snapshot `tests/contract/openapi.snapshot.json` diffed in CI. |
| API-2 | **One error envelope** (`application/problem+json`): `{type, title, status, code, detail, instance, request_id, errors[]}` for every 4xx/5xx incl. 404/405/validation/500; `code` is a member of `ErrorCode(StrEnum)` mapped to exactly one status; 500 bodies carry `{code: internal_error, request_id}` only; no body contains a Python identifier, class name or traceback fragment. | **[gate]** `tests/contract/test_problem.py` (every non-2xx the sweep produces validates; AST gate: no `HTTPException(` in `operator_ai/api`). |
| API-3 | **Status codes by semantics**: 201 + `Location` on create; 204 on delete; 404 on delete/revoke/cancel of an unknown id (rowcount checked); 409 for state conflicts (`hook_failed`, `conflict_decided`, `conflict_claimed`); 412 for version mismatch, 428 when `If-Match` is required and missing; 413 oversize; 415 bad media type; 422 only for client input; 429 always with `Retry-After` and `RateLimit-*`; 503 with `Retry-After` for busy/unseeded. | **[gate]** `tests/contract/test_verbs.py` over the walked router. |
| API-4 | **No client value produces a 5xx.** Shared `Id = Annotated[int, Path(ge=1, le=2**63-1)]`, `OptId`, `IdList` (repeat params, max 200), `Limit` (1..200), `Cursor` (pattern, max 200); strings bounded; filters typed as `Literal`/`StrEnum`. | **[gate]** `tests/contract/test_inventory.py::test_bounded_params`; `scripts/api_sweep.py` with id values `{0, -1, 2**63, 2**64, "abc", "²"}` and extra-field bodies → 404/422 never 5xx. |
| API-5 | **Strict bodies.** Every request model inherits `StrictModel` (`extra="forbid"`); no `dict`/`Any` body fields (typed sub-models or discriminated unions). | **[gate]** `tests/contract/test_inventory.py::test_strict_bodies`; `grep -rn ": Any\b\|dict\[str, Any\]" operator_ai/api/*.py operator_ai/schemas/*.py` = 0 outside documented JSON-patch bodies. |
| API-6 | **Collections paginate.** Every list route returns `Page[T] = {items, next_cursor, has_more, total?}` with keyset cursors; `limit` ≤ 200 uniform; unknown query params → 422 `unknown_parameter`; counts share the list's filter model. | **[gate]** `tests/contract/test_pagination.py` (1,000-row fixtures paged to completion with no gaps/duplicates under concurrent inserts; counts equal sum of pages; tampered cursor → 422). |
| API-7 | **Idempotency.** `Idempotency-Key` honoured on every POST that creates or enqueues (stored `(tenant, user, key) → status+body` for 24 h; same key + different payload hash → 409 `idempotency_conflict`); required (428) on `/burst`, `/studio/run`, `/academy/build`, `/evals/run`, `/prospects/imports`, `/team/students/import`, `/webinars/chains`. | **[gate]** `tests/contract/test_idempotency.py`. |
| API-8 | **Optimistic concurrency on decisions.** Editable resources expose `version` and a weak `ETag`; `PUT /queue/{id}`, `/approve`, `/reject`, `/send-now`, `PUT /prospects/{id}`, `/proposals/{id}`, `/webinars/{id}`, `/clients/{id}` accept `If-Match` or `expected_version`; mismatch → 412 with the current representation; the claim is `... AND version=?`; the approve audit row stores `{version, body_sha256, request_id}`. | **[gate]** `tests/contract/test_ifmatch.py` (edit-between-view-and-approve → 412, nothing routed; approve with matching version routes exactly that body; audit hash = sha256 of routed body). |
| API-9 | **Versioned path** `/t/{tid}/api/v1`; `/t/{tid}/api` alias for one release with `Deprecation` and `Sunset` headers (≥ 90 days); `X-API-Version` on every response; provider-registered webhook and public-page URLs never change; `docs/API_VERSIONING.md`. | **[gate]** `tests/contract/test_versioning.py`. |
| API-10 | **Resource naming** per `docs/API_STYLE.md`: plural nouns, kebab-case, no implementation names (`tid_`), no singular/plural pairs, one public-page family `/p/{tid}/{kind}/{token}`, one MCP mount `/t/{tid}/mcp`, actions as `POST /{resource}/{id}/{verb}` only where no method fits. | **[gate]** `tests/contract/test_naming.py` (segment regex, no `_` suffix params, no singular/plural pairs, no duplicate handler per path family). |
| API-11 | **Authorization is declarative.** Every rule is a dependency (`require(tab)`, `require_role(*roles)`, `require_owner`, `require_owner_or_subject(param)`, `require_item_owner(loader)`, `public(policy=...)`, `deny_in_demo`); no `ctx.role` comparison inside a route body; `docs/API_PERMISSIONS.md` generated. | **[gate]** `tests/contract/test_authz_declared.py` (AST: no `ctx.role` Compare in router-decorated functions; owner dependency on every `/academy/admin`, `/kb`, `/vault`, `/tenants`, `/mcp/tokens`, `/demo/reset`, `/claims` route); generated doc diffed. |
| API-12 | **Rate limiting is one policy-driven dependency** `limited(cls)` with classes `{ai 30/min/user + 300/h/tenant, heavy 6/h/user, write 120/min/user, read 600/min/user, login 8/15 min/ip+user before scrypt, public per /32 or /64}`, state in SQLite (Redis when `OPERATOR_MULTIPROCESS=1`), `RateLimit-*` + `Retry-After` headers, applied to every authenticated expensive route; per-tenant AI concurrency semaphore (429 `ai_busy`). | **[gate]** `tests/contract/test_ratelimit.py` (limits hold across two app instances; a coach is limited on `/coach/ask`; login limited before scrypt by timing; `grep -rn "_recent_views\|_rl =\|_throttled" operator_ai` = 0). |
| API-13 | **Long-running work** uses one Operation resource: heavy routes answer `202 {operation_id, status_url}`; `GET /operations/{id}` `{state, progress, result_url, error, request_id}`; `POST /operations/{id}/cancel`; AI calls run on a bounded executor; `/health` answers under load. | **[gate]** `tests/contract/test_operations.py` (each heavy route 202 within 100 ms; `/health` answers while 100 fake-LLM asks are in flight; cancel works). |
| API-14 | **Streaming.** `POST /coach/ask` and `/chat` with `Accept: text/event-stream` emit `token\|step\|citation\|done` events with ids and `Last-Event-ID` resume; `GET /runs/{id}/events` streams steps; `GET /t/{tid}/api/v1/events` publishes entity-change events; middlewares never buffer `text/event-stream`; the banned-name scrub runs in the answer layer. | **[gate]** `tests/contract/test_sse.py` (first event < 500 ms with the fake LLM; banned names never appear in streamed text; resume yields no duplicate tokens; JSON and SSE final answers identical). |
| API-15 | **Integration surface.** Per-user scoped API/MCP tokens (90-day default expiry, max 365, `last_used_at`, prefix-only display, opaque value with registry index, 404 on unknown revoke, audit row per `tools/call`); outbound webhook subscriptions (https-only, private ranges refused, HMAC-SHA256 over `ts.body`, 5 retries then dead-letter, deliveries list, ping); CORS for token-authenticated `/api/v1` only from `OPERATOR_ALLOWED_ORIGINS`; `HEAD` for every `GET`. | **[gate]** `tests/contract/test_tokens.py`, `tests/contract/test_webhooks_out.py`, `tests/contract/test_cors.py`. |
| API-16 | **Public endpoint inventory is generated** from the router (`scripts/gen_public_inventory.py` → `docs/PUBLIC_ENDPOINTS.md`), each public route declaring its abuse policy (throttle class, token entropy, body cap) in its decorator; `/openapi.json` served only to a signed-in owner (sanitised partner spec optional). | **[gate]** CI diff of the generated doc; `tests/contract/test_public_inventory.py`; unauthenticated `/openapi.json` → 404. |

## 4. Security (SEC)

| id | requirement | measure |

## 9. Product parity (PAR) — "everything Jeremy AI can do, better, provable"

Parity is measured against the vendor's public claims (`docs/audits/2026-10-27-research-refresh.json`), not against
marketing adjectives. Each line is a capability that must exist, be switched on by the owner, and be covered by a
named test. INV-1..5 bound every item: no capability may bypass approval, impersonate, clone a voice or make claims.

| id | capability | measure |
|---|---|---|
| PAR-1 | **Corpus ingestion at their scale**: Drive folder sync (kept), plus URL, YouTube/podcast transcript, audio/video (local Whisper), DM/email export parsers (Instagram, Telegram, Gmail mbox), call-recording imports with speaker labels and consent flags; every file screened by `content_policy` and staged for owner approval; 577k-word benchmark raised to ≥ 5 M words with p95 search < 50 ms. | **[gate]** `tests/parity/test_ingest.py` per source; `scripts/load_test.py` corpus benchmark in nightly CI. |
| PAR-2 | **Long input and files**: chat input ≥ 150k characters, files ≥ 100 MB (xlsx, pptx, audio, images via OCR), link reading (SSRF-safe), all through the sandboxed parser as operations. | **[gate]** `tests/parity/test_long_input.py`. |
| PAR-3 | **Answer latency with AI on**: first streamed token p95 < 1 s, full answer p95 < 6 s on the fixture corpus with the real provider in the nightly job (never advertised against the vendor's "under 2 s" claim without this evidence). | **[gate]** nightly perf job records it in `docs/evidence/`. |

## 10. How the ids are used

- A PR description names the ids it satisfies or touches; the reviewer checks each cited id's measure.
- `tests/test_arch.py`, `tests/contract/`, `tests/security/`, `tests/ops/`, `tests/kernel/`, `tests/domain/`,
  `tests/ai/`, `tests/parity/` and `web/e2e/` carry a docstring per test naming the id(s) it proves; `scripts/gen_standard_coverage.py`
  writes `docs/evidence/standard_coverage.md` (id → proving tests) in CI and fails on any **[gate]** id without a test.
- `docs/REBUILD_PLAN.md` maps every module to the ids it must satisfy and the phase in which it gets there.
